This change extends the existing Website Studio and approved customer design. It is for `rise-roost-experience-preview` and its separate D1 database `21352b95-d7f6-406f-8527-4b8dbcebf1bf` only. It must remain unmerged into production. No Supabase, Register/Admin, Square, DNS, GoDaddy, beta Worker, or custom domain change is part of this release.

## Data, safety and history

No SQL migration is required: all new fields are additive JSON inside existing versioned workspace ledgers. Existing `picked-up` rows, accepted orders/prices, credentials, content, membership and product records are preserved. Historical orders receive no retroactive policy/deadline. A new order stores policy version, server acceptance timestamp, original pickup, calendar snapshot and deadline. Extensions retain approval actor, time, original schedule, previous deadline and complete history. Customer responses omit private owner identifiers, verification references and internal audit.

Orders reserve inventory atomically when placed, through the existing D1 compare-and-swap ledger transaction. Browsing/abandoned baskets reserve nothing. A saved unpaid order remains a real reservation until the owner explicitly cancels/releases it; leaving a payment app neither releases stock nor verifies payment. This avoids silently deleting a customer's saved order. Physical stock reservations span pickup dates; preorder production limits apply per date. Extensions move the collection arrangement while retaining the original production reservation, since already scheduled/prepared goods are not a new production order.

Owner actions retain existing operation IDs, conflict checks and server-confirmed reconciliation. Customer message retries use a request identifier, input bounds, honeypot, per-network throttling, private order bearer and atomic ledger saves. A single persisted attention item is the in-app notification; external email/push alerts remain disabled. Owner replies and approvals are visible on five-second polling, focus and reconnection. No payment webhook, Square call, automatic verification, forfeiture or refund is implemented.

The shared temporary PIN identifies an authenticated owner device, not an individually proven Danielle identity. Individual owner accounts/passkeys/recovery remain a production launch prerequisite. New commerce behavior has a runtime isolation guard requiring review mode and the isolated D1 ID. PIN mode already requires the exact isolated host/database/workspace and refuses other hosts. These guards deliberately block simply moving this preview configuration to the official domain.

Preview storage remains bounded: 300 orders/workspace, 2,000 audited management operations, 100 messages/order, 1.2 MB ledger, 30 content revisions, 1.5 MB revision history, 500 member/comment directory records, and 8 MB in-app photo backup. A full private D1 backup/restoration rehearsal is required before release. Expand and migrate audited storage before business-scale production; the application refuses unsafe writes instead of silently removing order/payment history. Revision history retains 30 versions; export full backups for longer retention.

## Customer message recovery

The contact form keeps its unfinished draft and original retry identifier in that browser tab’s session storage, bound to a hash of the exact private tracking capability. It does not store the private access key. Refreshing preserves an unfinished or unconfirmed message. If confirmation is lost, the original message stays locked for a safe **Retry message** operation; the server acknowledges the same saved message instead of adding another. Generic HTTP 200 pages, wrong-order responses and replies without the specific message acknowledgment cannot clear the draft or count as a successful save. Server-confirmed messages clear the recovery record. Closing the tab, clearing browser data or blocking session storage can remove local draft recovery; confirmed messages remain on the server.

A pickup-help request without an alternative date still raises the extension-request indicator. Order questions stay Customer Contacted until resolved but do not create a new extension request unless pickup help or an alternative date is requested. Neither choice changes the confirmed schedule or approves more time.

## Operator-only complete preview backup

Danielle can continue using Studio's business-backup download. An operator can additionally run `python scripts/backup-experience-preview.py --plan` from `website/` to inspect the fixed scope without network or filesystem changes. To take a full private snapshot, supply `--isolated-preview --output-dir /private/new-backup-directory` with the configured Cloudflare account credentials already available through the supported environment. The parent directory must already exist; the chosen output directory must be new.

This tool reads only the fixed isolated experience D1, captures application tables and explicit indexes, restores into local SQLite, checks every restored record and the schema, and rereads the remote data to detect changes during export. It writes private local files and has no remote write/restore, database override, Worker deployment, DNS or production operation. Existing backup paths are refused. The snapshot includes private authentication verifiers and customer/order data: keep the entire directory private. It does not export the Worker pepper or restore production identity. A failed consistency check must be retried into a new directory and is not a verified backup. This is a repeatable operator backup tool, not a configured background backup schedule.

Alternative pickup dates and times are independently optional. A time-only suggestion displays the requested 12-hour clock time with “date not specified”; it never invents a date or changes the confirmed arrangement. An owner must still choose and confirm a dated future pickup.
