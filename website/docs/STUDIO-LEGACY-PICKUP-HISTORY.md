# Studio pickup history display correction

Legacy Tuesday pickup records were already excluded from customer availability, but Studio's upcoming list still displayed all future stored records, including closed, nonregular legacy dates. Studio now limits the upcoming list to regular Wednesday/Thursday/Friday windows and deliberately configured special pickups. Future nonregular legacy records appear in a collapsed **Older pickup records** section with an explanation that they are excluded from customer ordering. Past pickup dates retain their existing history section.

This is a presentation-only change to `public/management.mjs`. No dates, orders, settings, authentication, database records or checkout rules are changed. Explicit special pickups on other weekdays remain supported. The checkout date cards remain under **Choose your pickup**, in the desktop left column and below contact information on mobile. While ordering is paused, the existing pause message replaces available dates; opening ordering is a separate decision.

Validation uses disposable local production-style fixtures. The new browser regression inserts a closed legacy Tuesday and a deliberate special Tuesday, verifies Wednesday/Thursday/Friday and the special pickup in the upcoming list, checks collapsed history and keyboard expansion, confirms the legacy Tuesday cannot appear in customer availability, and fingerprints the complete original workspace row before/after viewing. It runs across desktop Chromium, desktop WebKit, iPhone WebKit, Android Chromium and tablet Chromium. Existing pickup-calendar backend tests and Studio navigation/Help regressions also run. The iPhone screenshot uses CSS-pixel scaling so the nine-week page stays within the browser's image-size limit.

Private production audits fingerprint all original rows across 13 tables, the full schema, Access application/policies and public ordering/payment settings. The deployed backend executable is reused exactly. No production orders, payments, calendar mutations or ordering activation are performed.

Final verification: **41 focused cases passed** — 21 pickup-calendar backend tests, five new calendar-history browser cases and 15 Studio navigation/Help browser cases. All five desktop/mobile profiles passed with zero unresolved failures or skips. Screenshots are in ignored `website/qa-results/calendar-history/`.
